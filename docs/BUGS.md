Fixed and verified. `supabase/migrations/20260915040000_admin_set_result_status_sync.sql` (adds the missing `status` writes alongside every existing `state` write in `admin_set_result_impl`, no other behavior change) applied by the developer in Supabase Dashboard SQL Editor. Verified directly: created a throwaway test tournament with a match in `state: "playing"`/`status: "active"`, called `admin_set_result_impl` with a winning score, and confirmed the returned match now has `state: "finished"` **and** `status: "completed"` together (previously `status` would have stayed stuck at `"active"`). Test row cleaned up via `finalize_tournament` afterward.

Pass 1 fixed the rule's scoping (it was `body:not(.landing-active)`, inherited from this stylesheet's unrelated file-wide "landing excluded from surface rules" convention, so landing's own hero heading was the one place still showing it) but kept the original `:not(:focus-visible)` guard. Developer reported the border still showing on Styring after that — pass 2 found why: the guard depends on `:focus-visible`, and WebKit/Safari's heuristic treats a scripted `.focus()` call as "visible" far more often than Chromium's does, so the outline kept showing there regardless of page. ## Bug completion rule

A bug is complete only when:

- [ ] Reproduced or clearly verified.
- [ ] Smallest safe fix implemented.
- [ ] Relevant behavior tested.
- [ ] Critical-path regression checked.
- [ ] Status updated.

Do not spend time producing long bug-analysis documents.
